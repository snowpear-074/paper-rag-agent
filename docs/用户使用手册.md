## 一、这个系统能做什么

把你手头的论文（PDF / Word / Markdown / TXT）导入系统，然后用自然语言提问。与直接用大模型对话的区别在于：

| 能力 | 说明 |
| --- | --- |
| **答案有出处** | 每个事实性陈述后面都带 `【论文名 p.页码】` 引用角标，点击可跳转到原文片段 |
| **找不到就说找不到** | 知识库里没有相关内容时，系统会明确告知，而不是凭印象编造 |
| **推理过程可见** | 右侧面板展示 Agent 完整的 `思考 → 调用工具 → 观察结果` 轨迹，你能看到它是怎么一步步得出结论的 |
| **能对比多篇论文** | 内置论文对比工具，可对照方法、数据集、实验结果 |
| **完全离线可用** | 默认配置下不访问任何外部服务，不需要 API Key，不上传你的论文 |

## 二、环境要求与安装

### 2.1 环境要求

| 项 | 要求 | 说明 |
| --- | --- | --- |
| Python | **3.10 或更高** | 项目使用了 PEP 604（`X | None`）语法，3.9 及以下无法运行 |
| NumPy | ≥ 1.24 | **唯一必需的第三方依赖** |
| 操作系统 | Windows / Linux / macOS | 已在 Windows 11 与 Linux 上验证 |
| 内存 | ≥ 4 GB | 主要消耗在向量索引（27 个分块的样例语料仅需数十 MB） |
| 浏览器 | 任意现代浏览器 | 前端为原生 JS，无构建步骤、无 CDN 依赖 |

### 2.2 安装步骤

**第 1 步：确认 Python 版本**

```bash
python --version
# 期望输出：Python 3.10.x 或更高
```

如果低于 3.10，请先升级 Python。Windows 用户可从 python.org 下载安装包，安装时勾选「Add Python to PATH」。

**第 2 步：安装 NumPy（唯一的必需依赖）**

```bash
pip install numpy
```

**第 3 步：进入项目目录**

```bash
cd "智能科研助理 —— 基于RAG+Agent的论文知识库问答系统"
```

**第 4 步：启动（无需其它安装步骤）**

```bash
python run.py
```

首次运行会自动创建所需的数据目录（`data/`、`logs/`、`reports/`），并在控制台打印启动横幅与服务地址。

### 2.3 两种运行模式

系统支持两种模式，通过 `config.yaml` 的 `llm.provider` 切换：

#### 模式 A：零依赖离线模式（默认，开箱即用）

```yaml
llm:
  provider: mock
```

- **优点**：不需要任何外部服务、不需要 GPU、不需要 API Key，启动即用
- **适用场景**：功能演示、链路验证、单元测试、无网络环境
- **重要说明**：`mock` 不是随机输出，而是一套**确定性的抽取式启发式**：它会从检索到的论文片段中挑出与问题最相关的句子，按"背景-方法-结果"的结构组织成答案，并保留引用标记。因此**检索与引用链路是完全真实的**，只有最后的"语言组织"是模板化的 —— 答案读起来会偏像"原文摘录汇编"，而不是流畅的解说。
- **想获得自然语言回答，请使用模式 B**

#### 模式 B：接入 Ollama 本地模型（推荐）

好处：完全离线、数据不出本机、答案自然流畅。

```bash
# 1) 安装 Ollama：https://ollama.com/download
# 2) 拉取模型（约 4.7 GB）
ollama pull qwen2.5:7b
# 3) 确认服务在运行
ollama serve
```

然后修改 `config.yaml`：

```yaml
llm:
  provider: ollama          # 从 mock 改为 ollama
  model: qwen2.5:7b
  base_url: "http://127.0.0.1:11434"
```

或者不改配置文件，用环境变量临时切换：

```bash
# Windows PowerShell
$env:APP_LLM__PROVIDER="ollama"
python run.py

# Linux / macOS
APP_LLM__PROVIDER=ollama python run.py
```

**还可以顺便升级 Embedding**（强烈建议，见 [6.4](#64-如何换-embedding-模型)）：

```bash
ollama pull bge-m3
```

```yaml
embedding:
  provider: ollama
  model: bge-m3
  dimension: 1024        # bge-m3 的维度
```

> ⚠️ 换 Embedding 模型后**必须重建索引**（见 [6.4](#64-如何换-embedding-模型)），否则新旧向量维度不一致会直接报错。

#### 模式 C：接入 OpenAI 兼容接口

适用于 OpenAI、DeepSeek、vLLM、LM Studio、硅基流动等任何提供 `/v1/chat/completions` 的服务。

```yaml
llm:
  provider: openai
  model: deepseek-chat
  base_url: "https://api.deepseek.com"    # 不用写 /v1，系统会自动补
  api_key: "sk-你的密钥"
```

**安全建议**：不要把密钥写进 `config.yaml`（容易误提交到版本库）。用环境变量：

```bash
# Windows PowerShell
$env:APP_LLM__API_KEY="sk-你的密钥"
$env:APP_LLM__PROVIDER="openai"
python run.py
```

### 2.4 可选增强依赖

以下依赖**都不是必需的**。装了系统会自动探测并启用（无需改代码），没装则使用内置实现：

| 依赖 | 安装命令 | 装了之后的提升 |
| --- | --- | --- |
| `pymupdf` | `pip install pymupdf` | PDF 解析速度与版面分析能力大幅提升（推荐） |
| `pypdf` | `pip install pypdf` | PDF 解析更稳，纯 Python |
| `python-docx` | `pip install python-docx` | Word 解析更完整 |
| `openpyxl` | `pip install openpyxl` | 评测报告可导出 Excel（不装则只输出 JSON + Markdown） |
| `PyYAML` | `pip install PyYAML` | YAML 解析更标准（不装则用内置子集解析器） |
| `jieba` | `pip install jieba` | 中文 BM25 分词更准 |
| `sentence-transformers` | `pip install sentence-transformers` | 本地真实语义向量模型 |

一条命令装齐推荐项：

```bash
pip install pymupdf openpyxl PyYAML jieba
```

## 四、界面功能说明

界面为**三栏布局**：左侧知识库与会话管理，中间对话区，右侧 Agent 推理轨迹。

### 4.1 顶栏

| 元素 | 说明 |
| --- | --- |
| 系统名称 | 左上角标题 |
| **健康状态指示灯** | 绿色=全部组件正常；黄色=部分组件降级（如 LLM 未连接）；红色=初始化失败。鼠标悬停显示详情 |
| **指标** 按钮 | 打开系统指标面板（KPI / 工具调用 / 终止原因 / 检索质量 / 最近问题） |
| **工具** 按钮 | 查看全部已注册工具及其参数说明 |
| **主题** 按钮 | 在浅色 / 深色 / 跟随系统之间切换 |

### 4.2 左侧栏（知识库与会话）

**会话区**

| 元素 | 说明 |
| --- | --- |
| **新建会话** 按钮 | 创建一个空白会话，历史记录互相隔离 |
| 会话列表 | 点击切换；每个会话独立维护上下文与摘要 |
| 重命名 / 删除 | 对话区标题旁的两个按钮，作用于当前会话 |

**知识库区**

| 元素 | 说明 |
| --- | --- |
| **拖拽上传区** | 把 PDF / DOCX / TXT / MD 文件直接拖进来即可上传；也可点击选择文件（支持多选） |
| 上传进度列表 | 显示每个文件的解析 → 分块 → 向量化 → 入库进度百分比 |
| **刷新** 按钮 | 重新拉取文档列表 |
| 文档列表 | 每篇论文显示标题、页数、分块数；点击可展开查看详情；右侧有删除按钮 |
| **统计卡片** | 文档数 / 分块数 / 向量数三个实时指标 |

### 4.3 中间对话区

| 元素 | 说明 |
| --- | --- |
| 消息气泡 | 用户消息与助手回答；助手回答支持 Markdown 渲染（标题、列表、表格、代码块、引用块） |
| **引用角标** | 形如 `[1]` 的上标，点击弹出该来源的原文片段与页码 |
| 引用卡片 | 回答下方的来源列表，显示论文名、页码、相关度、原文预览 |
| 降级提示条 | 检索无结果或相关度过低时，回答上方会出现黄色提示条，说明降级原因 |
| 输入框 | `Enter` 发送，`Shift + Enter` 换行；支持多行长问题 |
| **发送** / **停止** 按钮 | 生成过程中「发送」变为「停止」，可随时中断流式输出 |
| 空状态引导 | 知识库为空时显示引导卡片，提示先上传论文或一键导入样例 |

### 4.4 右侧栏（Agent 推理轨迹）

这是本系统区别于普通问答产品的核心功能 —— **把 AI 的思考过程摊开给你看**。

| 区域 | 说明 |
| --- | --- |
| **统计条** | 推理轮次 / 工具调用次数 / 工具成功率 |
| **时间线** | 按顺序展示每一步：<br/>🟣 `route` 路由决策（含置信度）<br/>🔵 `thought` 模型的思考<br/>🟠 `action` 调用的工具与参数<br/>🟢 `observation` 工具返回的结果（截断显示）<br/>🔴 `error` 错误与恢复提示<br/>⚫ `final` 最终答案 |
| **JSON** 按钮 | 切换到原始轨迹 JSON 视图（便于复制出来做分析） |
| **清空** 按钮 | 清空当前轨迹面板 |

**怎么用它排查问题**：如果答案不对，先看时间线里 `knowledge_search` 的 `query` 参数 —— 如果模型改写后的问题偏离了你的原意，问题出在 Agent 理解环节；如果检索返回的片段本身就无关，问题出在检索环节（调整检索参数或换 Embedding 模型）。

### 4.5 指标面板

点击顶栏「指标」按钮打开，包含五个区块：

| 区块 | 内容 |
| --- | --- |
| **核心 KPI** | 总请求数、缓存命中率、降级率、平均延迟、Token 总消耗、估算成本 |
| **工具调用** | 每个工具的调用次数、失败次数、成功率、平均耗时 |
| **终止原因分布** | `final_answer` / `max_iterations` / `loop_detected` / `parse_error` 各自占比 |
| **检索质量** | 平均召回条数、平均相关度、Top-1 相关度分布 |
| **最近问题** | 最近若干条问答的问题、延迟、是否命中缓存、是否降级 |

面板右上角有「自动刷新」开关。

## 五、典型使用流程

### 5.1 完整流程：从上传论文到拿到带引用的答案

**第 1 步：准备论文**

把 PDF 文件放在任意目录（不要在系统运行目录下随意改动文件）。

**第 2 步：上传并建索引**

方式一（界面）：把文件拖进左侧「知识库」区域的虚线框，等待上传列表里每个文件显示「完成」。

方式二（命令行）：

```bash
python run.py --index "D:/论文/Transformer.pdf" --strategy paper
```

方式三（批量）：

```bash
python run.py --index "D:/我的论文集" --strategy paper
```

> **提示**：学术论文强烈建议用 `--strategy paper`；界面上的上传默认使用 `config.yaml` 里的 `chunking.strategy`。

**第 3 步：确认索引成功**

左侧「统计卡片」应显示文档数与分块数都大于 0。点开文档列表可以看到每篇论文的分块数。

**第 4 步：提问**

在输入框里输入问题，例如：

```
Transformer 训练用了哪些数据集？
```

**提问技巧**：

- 用论文里出现过的**术语**提问，效果最好。例如问「WMT 2014 英德任务的 BLEU 是多少」比问「这个模型效果好吗」更容易命中
- 数字、数据集名、模型名这类**专有信息**是检索的强信号，尽量写进问题
- 中文提问时**保留英文术语**（如 `ImageNet`、`masked language model`），因为语料多为英文，英文术语能显著提升召回
- 一次只问一件事；需要对比时明确说出来（"对比 A 和 B 的方法"），Agent 会调用论文对比工具

**第 5 步：查看引用**

答案里的 `[1]` `[2]` 角标可点击。点击后弹出该来源的论文名、页码与原文片段 —— 这是核查答案是否可靠的最快方式。

**第 6 步：查看推理轨迹**

看右侧面板确认：Agent 是否检索了知识库？检索用的 query 是什么？检索到了几个片段？相关度多少？如果相关度普遍很低（低于 0.25），答案上方会出现降级提示。

### 5.2 场景示例

**场景 A：查具体实验数字**

```
问题：big transformer 在 WMT 2014 英德任务上的 BLEU 分数是多少？
预期：答案给出 28.4，并标注【Attention Is All You Need p.2】
```

**场景 B：理解一个方法**

```
问题：Scaled Dot-Product Attention 是怎么计算权重的？
预期：Agent 检索到定义段落，答案给出"点积 → 除以 sqrt(dk) → softmax"的完整步骤
```

**场景 C：对比两篇论文**

```
问题：对比 Transformer 与 ResNet 在解决"训练难"这个问题上的思路差异
预期：Agent 调用 paper_compare 工具，答案从两篇论文分别取证并给出对照
```

**场景 D：知识库外的内容（验证降级）**

```
问题：今天天气怎么样？
预期：系统判定为低相关，明确告知"知识库中未找到相关内容"，不编造答案
```

## 六、配置说明

所有配置集中在项目根目录的 `config.yaml`。**优先级**：`内置默认值 < config.yaml < 环境变量 APP_* < 代码传参`。

环境变量命名规则为 `APP_<段名>__<字段名>`（双下划线分层），例如 `APP_RETRIEVAL__TOP_K=10`。

### 6.1 如何切换到 Ollama

```yaml
llm:
  provider: ollama
  model: qwen2.5:7b
  base_url: "http://127.0.0.1:11434"
  temperature: 0.3
  timeout: 120
```

切换后用 `python run.py --health` 确认 LLM 状态为 `ok: true`。健康检查会列出 Ollama 中已安装的模型，并提示你配置的模型是否已 pull。

### 6.2 如何切换到 OpenAI 兼容接口

```yaml
llm:
  provider: openai
  model: deepseek-chat
  base_url: "https://api.deepseek.com"
  api_key: ""                # 留空，改用环境变量 APP_LLM__API_KEY
```

```bash
$env:APP_LLM__API_KEY="sk-你的密钥"
python run.py
```

### 6.3 如何调整检索参数

检索相关参数集中在 `retrieval` 段：

| 参数 | 默认 | 调大的效果 | 调小的效果 |
| --- | --- | --- | --- |
| `top_k` | 5 | 更多片段进入 Prompt，召回更全，但噪声与延迟上升 | 上下文更聚焦，但可能漏掉证据 |
| `candidate_k` | 20 | 融合与重排序的候选池更大，召回上限更高，延迟上升 | 更快，但可能筛掉正确答案 |
| `enable_bm25` | true | — | 关闭后专有名词/数字匹配能力显著下降（**不建议关**） |
| `enable_rerank` | true | — | 关闭可省排序开销；实测在某些问题上排序质量反而更好 |
| `rrf_k` | 60 | 更看重"多路共同命中" | 更放大单路的头部排名 |
| `low_relevance_threshold` | 0.25 | 更容易触发降级（更保守） | 更容易放行低相关片段（更容易编造） |

**调参建议**：

- **检索结果不相关** → 先看轨迹里的实际召回内容。如果召回的就是无关片段：把 `candidate_k` 调到 30~40；如果问题里有明确的专有名词却召回失败，确认 `enable_bm25=true`
- **答案缺少关键信息** → 把 `top_k` 调到 8，把 `generation.max_context_chars` 从 6000 调到 8000
- **响应太慢** → 检查是检索慢还是生成慢（看指标面板的延迟分解）。本地小模型生成慢是常态，可换更小的模型
- **不想让系统回答知识库外的问题** → 把 `low_relevance_threshold` 从 0.25 调到 0.35~0.4

### 6.4 如何换 Embedding 模型

这是**提升检索质量最有效的一步**，尤其是中文提问检索英文语料的场景。

**步骤 1：拉取模型**

```bash
ollama pull bge-m3
```

**步骤 2：确认维度**

| 模型 | 维度 |
| --- | --- |
| `bge-m3` | 1024 |
| `bge-large-zh` | 1024 |
| `nomic-embed-text` | 768 |

**步骤 3：修改配置**

```yaml
embedding:
  provider: ollama
  model: bge-m3
  dimension: 1024
  base_url: "http://127.0.0.1:11434"
```

**步骤 4：重建索引（必须！）**

旧索引是用旧模型的向量生成的，维度与语义空间都不同，**必须全部删除重建**：

```bash
# 方式一：删掉索引目录后用命令行重新导入
rm -rf data/index data/vector_store      # Linux / macOS
Remove-Item -Recurse data\index, data\vector_store   # Windows PowerShell
python run.py --index "D:/我的论文集" --strategy paper

# 方式二：在界面里逐个删除文档后重新上传
```

> ⚠️ 不重建索引的典型症状：启动时报维度不匹配的错，或检索结果完全无意义。

### 6.5 如何清空知识库

```bash
# 停止服务后删除索引与向量库
Remove-Item -Recurse -Force data\index, data\vector_store     # Windows
rm -rf data/index data/vector_store                            # Linux / macOS
```

同时建议清空语义缓存（否则旧答案仍会被命中）：

```bash
Remove-Item -Force data\cache\semantic_cache.db    # Windows
rm -f data/cache/semantic_cache.db                 # Linux / macOS
```

也可以只删单个文档：在界面左侧文档列表里点该文档右侧的删除按钮。

### 6.6 调整模型与成本相关参数

```yaml
llm:
  temperature: 0.3        # 科研问答建议 0.1~0.3，越低越保守
  max_tokens: 1024        # 单次生成长度上限
  timeout: 120            # 本地模型首次加载可能很慢，可调到 300
  max_retries: 3          # 失败重试次数

generation:
  max_context_chars: 6000 # 拼进 Prompt 的上下文上限
  max_chunk_chars: 1500   # 单个片段截断长度
  cache:
    enabled: true
    similarity_threshold: 0.93   # 调低=更容易复用旧答案（有错答风险）
```

### 6.7 调整 Agent 行为

```yaml
agent:
  max_iterations: 8       # 最大推理轮次
  tool_timeout: 45        # 单工具超时（秒）
  enable_router: true     # 启用意图路由（省 Token、少选错）
  enable_parallel: true   # 并行工具调用
  loop_detect_window: 2   # 连续 N 轮相同调用即强制终止
```

## 八、常见问题 FAQ

### Q1：启动时报「端口被占用」

**现象**：`OSError: [WinError 10048] 通常每个套接字地址只允许使用一次`

**原因与解决**：系统在端口被占用时会**自动顺延**到下一个可用端口，请查看启动横幅中打印的实际地址。如果仍报错，手动指定端口：

```bash
python run.py --port 8600
```

查找占用端口的进程：

```powershell
netstat -ano | findstr :8501      # Windows
lsof -i :8501                     # Linux / macOS
```

### Q2：PDF 上传后解析不出文字（分块数为 0）

**可能原因与解决**：

1. **扫描版 PDF（图片型）**：本系统不含 OCR，无法处理。可用 Adobe Acrobat 等工具先做 OCR，或把文字复制成 TXT 后导入。
2. **中文 PDF 用内置解析器丢字**：内置解析器只处理 ASCII 文本。解决：`pip install pymupdf`，重启服务后系统会自动使用它。
3. **PDF 加密**：需要先解除密码保护。
4. **查看具体错误**：启动时加 `--log-level DEBUG`，或查看 `logs/` 下的日志文件。

```bash
python run.py --index "D:/某论文.pdf" --log-level DEBUG
```

### Q3：检索结果不相关，怎么调

按以下顺序排查（每一步都可通过右侧轨迹面板验证）：

1. **看轨迹里 `knowledge_search` 的实际 query**：如果模型改写后的问题偏离原意，换一种问法，或在问题里直接写论文中的术语。
2. **确认 BM25 已启用**：`retrieval.enable_bm25: true`。关闭后数字与专有名词匹配能力会显著下降。
3. **扩大候选池**：`candidate_k` 从 20 调到 30~40。
4. **增加返回条数**：`top_k` 从 5 调到 8。
5. **调整分块粒度**：`chunking.chunk_size` 从 512 调到 384（更聚焦）或 768（更完整）。改完**必须重建索引**。
6. **换 Embedding 模型**（根本解法，见 [6.4](#64-如何换-embedding-模型)）：默认的 `hash` 是词面近似，没有跨语言语义能力。
7. **中文提问尽量保留英文术语**：语料是英文时，`ImageNet`、`BLEU`、`masked language model` 这类术语能靠 BM25 命中。

### Q4：如何清空知识库

见 [6.5](#65-如何清空知识库)。要点：删 `data/index` 与 `data/vector_store` 两个目录，并顺手清 `data/cache/semantic_cache.db`，否则旧答案会被语义缓存命中。

### Q5：如何换 Embedding 模型

见 [6.4](#64-如何换-embedding-模型)。**最关键的一点：换了模型必须重建索引**，否则新旧向量维度不匹配。

### Q6：离线模式为什么答案像模板

因为 `llm.provider=mock` 时，最后的"语言组织"环节由**确定性抽取式启发式**完成：它从检索到的片段里挑选与问题关键词重叠度最高的句子，按固定格式拼装，并保留引用标记。

**这不是 bug，而是刻意的设计**：mock 后端的目标是"让整条链路（检索 → 引用 → Agent 决策 → 评测）在无外部依赖时可复现地跑通"。所以：

- ✅ 检索结果是真实的
- ✅ 引用来源与页码是真实的
- ✅ Agent 的工具选择与推理轮次是真实的
- ❌ 答案的自然语言表达是模板化的

想要自然流畅的回答，请切换到 Ollama（[6.1](#61-如何切换到-ollama)）或 OpenAI 兼容接口（[6.2](#62-如何切换到-openai-兼容接口)）。

### Q7：提示「无法连接 Ollama」

**排查步骤**：

```bash
# 1) Ollama 服务是否在跑？
ollama list

# 2) 没跑就启动（新开一个终端窗口保持运行）
ollama serve

# 3) 模型是否已拉取？
ollama pull qwen2.5:7b

# 4) 服务地址是否与 config.yaml 一致？
curl http://127.0.0.1:11434/api/tags
```

如果 Ollama 装在另一台机器上，把 `llm.base_url` 改成对应地址（如 `http://192.168.1.100:11434`），并确保对方 Ollama 监听 `0.0.0.0`。

### Q8：回答里出现了论文里没有的内容（幻觉）

系统已通过三层机制抑制，但仍不能 100% 杜绝：

1. **提示词约束**：明确要求"只依据参考资料，资料不足时明说"
2. **强制引用**：每个事实都要标注来源，便于你核查
3. **`rag_strict` 模板**：更严格的模板，要求每一句都能在资料里找到直接依据

**建议措施**：

- 用 `rag_strict` 提示词（在代码中切换 `prompt_name="rag_strict"`）
- 把 `llm.temperature` 降到 0.1
- **看到引用角标就点开核对** —— 这是最可靠的手段
- 运行评测时关注 `citation_accuracy` 指标（引用准确率），它能自动识别"引用了不存在的来源"

### Q9：响应很慢

**先定位瓶颈**：打开指标面板，看延迟分解里的"检索耗时"与"生成耗时"。

| 瓶颈 | 典型耗时 | 解决方向 |
| --- | --- | --- |
| 生成 | 数秒~数十秒 | 正常现象（本地 7B 模型）。换更小的模型，或改用云端 API |
| 检索 | < 100ms | 通常不是瓶颈。若异常高，检查 `candidate_k` 是否设得过大 |
| 首次请求 | 数十秒 | Ollama 首次加载模型到显存需要时间，之后会快很多 |
| 缓存未命中 | — | 相同问题问第二遍会命中语义缓存，延迟降到毫秒级 |

### Q10：Agent 一直调用工具，不给答案

**可能原因**：

1. **问题过于宽泛**（如"介绍一下这些论文"）→ 让问题更具体
2. **`max_iterations` 太小** → 从 8 调到 12
3. **模型指令遵循能力弱** → 换更大的模型，或确认 `enable_router: true`（路由能缩小候选工具集，减少选错）

**注意**：即使真的达到轮次上限，系统也会**用已收集到的信息生成答案**，而不是返回空白。这类情况在指标面板的「终止原因分布」里会记为 `max_iterations`。

### Q11：中文提问检索不到英文论文

这是当前系统的**已知局限**。默认的 `hash` Embedding 是词面近似，没有跨语言语义能力。

**立即可用的缓解手段**：在中文问题里保留英文术语。例如：

- ❌ 「这个模型用什么数据训练的」→ 几乎检索不到
- ✅ 「Transformer 用了哪些数据集，WMT 2014 有几百万句对」→ 靠 `Transformer`、`WMT 2014` 命中

**根本解法**：切换到 `bge-m3` 等支持多语言的 Embedding 模型（见 [6.4](#64-如何换-embedding-模型)），然后重建索引。

### Q12：上传文件大小/格式限制

| 项 | 限制 |
| --- | --- |
| 支持格式 | `.pdf` `.docx` `.txt` `.md` `.markdown` `.csv` `.json` `.bib` |
| 单文件大小 | 默认 100 MB（`server.max_upload_mb`） |
| 单次上传数量 | 界面支持多选；建议一次不超过 20 个文件 |

超过 100 MB 的文件，建议先在 `config.yaml` 里调大 `server.max_upload_mb`，或用命令行 `--index` 导入（命令行不受该限制）。

### Q13：忘记关闭服务，端口一直被占着

```powershell
# Windows：找到并结束进程
Get-Process python | Where-Object { $_.Path -like "*python*" } | Stop-Process
# 或按端口找
netstat -ano | findstr :8501
taskkill /PID <进程号> /F
```

```bash

```

### Q14：导入论文后，之前的答案还能查到旧内容

这是**语义缓存**导致的。知识库更新后建议清缓存：

```bash

rm -f data/cache/semantic_cache.db                 # Linux / macOS
```

或者把 `generation.cache.enabled` 临时设为 `false`。

# 1) Python 版本
