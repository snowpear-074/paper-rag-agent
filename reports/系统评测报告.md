**相关性判定口径**：采用 `match="text"` —— 把评测样本的 `gold_texts`（论文原文的连续片段）与检索片段做 4-gram 字符重合度比对，覆盖率 ≥ 0.5 即判定该片段相关。该口径与 :meth:`src.retrieval.engine.RetrievalEngine._match_texts` 完全一致。

**指标定义**：

| 指标 | 定义 | 说明 |
| --- | --- | --- |
| Hit@5 | Top-5 中是否至少有一条相关 | 召回底线，不反映排序 |
| MRR | 首个相关结果的倒数排名 | 反映“正确结果排得多靠前” |
| Recall@5 | Top-5 覆盖的金标准比例 | 多证据问题的关键指标 |
| Precision@5 | Top-5 中相关片段占比 | 上下文噪声水平 |
| NDCG@5 | 二值相关性的归一化折损累计增益 | 召回 + 排序综合指标 |
| 引用准确率 | 答案标注的来源是否真实存在于检索结果 | 检测引用幻觉 |
| 引用覆盖率 | 带引用的实质句子比例 | 答案可核查程度 |
| 忠实度 | 答案句子在上下文中可找到 4-gram 支撑的比例 | 检测生成幻觉 |
| Token-F1 / ROUGE-L | 与参考答案的词面重叠 | 生成质量近似指标 |

### 3.4 结论

- 混合检索（向量 + BM25，RRF 融合）相对纯向量：严格 Hit@5 0.6750 → 0.7000，严格 MRR 0.6100 → 0.5883，延迟 0.25 → 0.80 ms。BM25 补上的是**术语字面匹配**能力 —— 中文提问里的英文术语（WMT 2014 / BLEU / ImageNet / masked language model）正是靠这一路命中。
- 叠加启发式重排序后：严格 NDCG@5 0.5827 → 0.5681，严格 MRR 0.5883 → 0.5758，延迟 0.80 → 0.94 ms。**收益与代价请直接按这两列数据判断**：本次运行中重排序并未提升排序质量（反而略降），说明当前的六特征加权在某类问题上会误判 —— 是否默认开启 `retrieval.enable_rerank` 应以本表为准，而不是凭直觉。

## 七、一轮迭代优化的前后对比

两组配置在同一份语料上**真实运行**，差异仅在参数：


## 八、结论与优化建议

### 8.1 结论

- 检索层：在 27 个分块、中英混合提问（40 条）条件下，`hybrid` 档**严格 NDCG@5** 最高（0.5827，严格 Hit@5 0.7000）；延迟最高的是 `full`（0.94 ms）。三档对比说明「加能力」与「加延迟」是同一件事的两面，默认档位应按延迟预算选择。
- Agent 层：工具调用宽松准确率 100.0%、严格准确率 100.0%，平均 2.00 轮完成；终止原因分布 {'final_answer': 20}。工具选择的严格与宽松口径一致，首个工具选择稳定。
- 端到端：平均 1.83 ms 完成一次问答（检索占 1.08 ms、生成占 0.30 ms），缓存命中率 0.0%、降级率 15.0%；引用准确率 100.0%、忠实度 100.0%。检索耗时占比极低说明**瓶颈在生成侧**（本次运行 LLM provider=mock）。
- Bad Case：共 13 条（32.5%）；分类分布为 检索失败=13、生成错误=0、引用错误=0、决策错误=0。按严重度优先级，引用类问题应先修（可信度底线），检索类问题影响面最大。

### 8.2 优化建议（按优先级）

下表的「效果」栏：**已由本轮对照实验验证**的写实测变化，未验证的写预期方向。

| 优先级 | 问题 | 措施 | 涉及参数/模块 | 效果（实测/预期） |
| --- | --- | --- | --- | --- |
| P0 | 引用幻觉 | 生成后校验引用来源，不在检索结果中即标记「未核实」 | `generation` / `src/generation/rag_pipeline.py` | 消除误导性引用（本轮引用准确率 100.0%，40 条样本均未检出引用幻觉，全部样本忠实度 ≥ 0.5） |
| P0 | 启发式重排序误判 + 低相关降级率偏高 | 关闭 `retrieval.enable_rerank`，改用 RRF 融合分数作为置信度 | `retrieval.enable_rerank` | 严格 NDCG@5 实测 0.6238 → 0.6359（↑+0.0121）；降级率 实测 0.1639 → 0.0328（↓-0.1311） |
| P1 | 片段粒度与金标准粒度不匹配 | `chunk_size` 512→384 | `chunking.chunk_size` | 严格 Hit@5 实测 0.7705 → 0.8033（↑+0.0328） |
| P1 | 中文提问检索英文语料 | 把 `embedding.provider` 换成 ollama（bge-m3）等真实语义向量 | `embedding.provider` | 预期跨语言召回大幅提升（本轮 `hash` 词面向量无跨语言能力） |
| P2 | 上下文截断 | `max_context_chars` 6000→8000 | `generation.max_context_chars` | 预期更多证据进入 Prompt；本轮端到端延迟 实测 1.7767 → 1.5925（↓-0.1842） |
| P3 | 离线模式答案偏模板化 | 切换到 Ollama / OpenAI 兼容接口 | `llm.provider` | 预期答案自然度与推理深度提升（本轮 `llm.provider=mock`，答案由抽取式启发式生成） |
